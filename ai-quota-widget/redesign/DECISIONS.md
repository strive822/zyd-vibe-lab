# AI 额度悬浮窗 · 架构决策记录

版本：架构基线 v1.1，2026-09-25。需求以 [SPEC.md](SPEC.md) 为准，阶段与验收以 [PLAN.md](PLAN.md) 为准。

记录状态中的“已确认”指用户明确选择；“沿用/规划默认”指依据现状采取的最小方案，不表示新增产品需求已经得到用户口头确认。架构约束继续有效；本轮 UI 编码授权与覆盖范围见 ADR-011。

## ADR-001 · 历史架构任务仅交付文档（本轮 UI 授权见 ADR-011）

- **状态/依据**：已确认；用户明确表示只完成 1.ARCHITECT.txt，不要求修代码。
- **决策**：交付需求理解、风险分析、SPEC、阶段 PLAN、必要决策和窗口交接；不修改源码、测试、构建脚本、配置、二进制或运行进程，也不自动回滚前序改动。
- **原因**：架构规划与工程执行是不同任务，现有未提交修改需要保留现场。
- **后果**：本次“完成”仅指架构交付；未来工程任务须明确候选基线并核对差异，不能把本文当成发布授权。

## ADR-002 · 沿用现有 Windows 单体桌面架构

- **状态/依据**：沿用；当前 README 与源码为 C# / .NET Framework / WinForms。
- **决策**：保留单一常驻窗、设置、菜单、托盘、本机 JSON 与线程池。个人本机使用为规划默认；不新增 Web 服务、数据库、云同步或跨平台架构。
- **备选与取舍**：重写为 Web/Electron/新 .NET 栈会增加运行依赖、迁移和界面回归成本，当前问题可在现有结构内解决，因此不选。
- **维护代价**：需要专门做 Windows 原生控件、DPI 和系统集成验收；本机通过不等于全面系统兼容认证。

## ADR-003 · Codex 登录由官方客户端维护

- **状态/依据**：已确认；用户选择“只读跟随 Codex 登录”。
- **决策**：只读登录文件；401 仅在重读发现凭据/账号变化时再查一次 usage；403 独立处理。不请求 OAuth 续期、不创建/替换登录文件或备份。
- **备选与取舍**：保留自动续期便利，但必须与 Codex 进程共同处理 Token 更新、账号切换和文件冲突；本进程锁不能解决外部进程写入，因此不选。
- **维护代价**：登录失效时用户需在官方客户端处理；本工具随后重新读取恢复。客户端额度接口仍是外部兼容风险，与只读决策分开验收。

## ADR-004 · 稳定账号身份及配置来源保护

- **状态/依据**：沿用加固目标；前序审查已记录按数组位置保留字段会错配。
- **决策**：仅对多账号智谱配置增加稳定 ID；缺失/重复 ID 在内存修复，成功保存时持久化。扩展字段随账号深拷贝。损坏来源禁止保存，缺文件首次配置继续允许。
- **备选与取舍**：数组位置随删除调序变化；名称可重复；Key 可更换且不应作为持久标识；使用独立 ID 的复杂度最低。
- **维护代价**：旧配置第一次成功保存会增加 ID；设置草稿和以后迁移必须保留 ID/扩展字段/来源错误状态，不能只复制可见表单字段。

## ADR-005 · 调度集中，网络工作与 UI 状态分离

- **状态/依据**：规划默认；解决重复请求与过时结果回写的最小职责划分。
- **决策**：协调器持有每账号请求槽位、代次、到期及冷却。工作线程只使用不可变快照；结果回到 UI 线程后校验身份/代次再应用。取消后等请求实际退出才释放槽位。注入时钟、请求、分发以便测试。
- **备选与取舍**：继续由每个菜单/定时器分支独立发请求容易遗漏约束；引入完整工作流框架超过需要。沿用线程池和小型协调器。
- **维护代价**：需要真实阻塞/取消用例和清楚的线程归属，不能只靠纯函数退避测试证明并发正确。

## ADR-006 · 冷却优先，缓存归属清晰

- **状态/依据**：规划默认；与服务限流及“数据可信”目标一致。
- **决策**：429 等待至少为正常刷新周期，有效更晚的服务端期限优先；手动刷新、缩短间隔均不绕过。只保留同一账号最后有效数据；换凭据或实际 Codex 账号时清除旧缓存。
- **备选与取舍**：每次点击都立即请求会抵消退避；失败即清空所有旧值降低可用性；跨账号保留旧值容易误判，因此采用有归属的过期缓存。
- **维护代价**：UI 必须同时表达“有值”和“已过期”；全局完成时间不能暗示所有账号成功。

## ADR-007 · 以数据含义决定数值类型和容错粒度

- **状态/依据**：规划默认；前序合成输入已记录 NaN/越界时间/余额转换失败。
- **决策**：百分比使用有限数并限定范围；无效时间为未知且格式化再防御；金额直接解析 decimal。余额按币种行容错，可选赠送字段非法不影响合法总额；部分异常明确告知。
- **备选与取舍**：先 double 后 decimal 可能丢精度或溢出；把非法数字当 0 会误导；一行异常丢掉所有币种扩大错误影响，因此不选。
- **维护代价**：数据模型保留“未知/部分有效”语义；测试同时检查边界与用户可见状态。

## ADR-008 · 配置凭据仍在本机，预览从源头隔离

- **状态/依据**：沿用现状与已定范围，不新增凭据存储迁移。
- **决策**：现有 Key 继续保存于本机 JSON，输入遮蔽、不得提交仓库，不输出到日志/截图/报告；不声称加密保护。模拟模式在选择配置来源时即使用合成数据，并隔离实例与开机自启操作。
- **备选与取舍**：先加载真实配置再只替换网络响应仍会接触真实密钥；新增凭据库/加密迁移涉及备份和恢复策略，当前范围不承担，因此不选。
- **维护代价**：文件保护依赖当前用户环境；公开分发、多用户或同步需求出现时需重新评估凭据存储。

## ADR-009 · 可验证的暂存产物优先于固定别名

- **状态/依据**：沿用前序发现的进程占用事实；保留已有构建入口。
- **决策**：每次应用构建生成 bin 下独立命名暂存 exe，测试通过后再尝试替换正式 exe；输出实际路径。`.next.exe` 是尽可能更新的别名。支持 test-only/stage-only；失败返回非零，替换失败返回 3，不强制关闭已有进程。
- **备选与取舍**：只写 `.next.exe` 会被预览进程锁住；关闭用户进程影响正在使用的程序；直接覆盖正式文件也不满足验收隔离，因此采用独立暂存。
- **维护代价**：调用者必须辨认输出中的实际候选路径；过时暂存文件仅在明确的清理任务中移除，运行中的文件和当前候选须保留。

## ADR-010 · 局部 UI 先设计，验证证据分层（视觉范围由 ADR-011 替代）

- **状态/依据**：规划默认；用户选择全面加固现有版本，未要求视觉重做。
- **决策**：保留布局和现有余量色阶；先定义状态、文案、长内容和缩放边界，再做局部 UI 接线。离线测试、控件事件、渲染图、真实桌面 UAT 和在线查询分别记录。
- **备选与取舍**：整体重绘扩大回归面；把渲染图或一次接口成功当作完整验收会掩盖真实环境问题，因此不选。
- **维护代价**：真实托盘、DPI、多屏、透明混合仍需环境支持；无法验证时明确标注，不将其伪装成通过。

## ADR-011 · 像素能源控制器与暂存验收

- **状态/依据**：用户明确选择 A 方向、288px 紧凑宽度，并要求实施完整计划。
- **决策**：DESIGN.md 为冻结的设计身份；主窗、设置、菜单共用像素视觉系统，保留 WinForms、单常驻窗与现有全部业务语义。允许 UI 源码、必要回归及文档变更。
- **取舍**：使用系统字体和程序绘制的分段几何，不引入外部字体、Web 框架或装饰资产。数值、状态可读性优先。
- **验收**：独立暂存 exe、合成数据、实际窗口截图和离屏图分开记录。独立 Critic 审查后仍需用户最终人工验收；不自动替换正式程序。
- **范围覆盖**：替代 ADR-010 中保留旧布局/旧颜色的限制；ADR-001 描述的旧架构任务继续作为历史保留，不限制此次明确授权。
- **System Expansion 复审修正**：全局时间以「最近请求结束」明确表达过程事件，各账号独立表达数据有效性；配置损坏使整页进入只读/禁用状态，普通保存失败仍可编辑重试；金额使用三位分组及组间断行。依据用户指出的两个 P1 和一个 P2，细化同一视觉语言，不改变请求、认证或配置文件契约。

## ADR-012 · 透明边缘与不透明读数区

- **依据**：用户 R3 复审的 P1：全窗 70% 透明导致底层文字与账号、时间及能量条混在一起。
- **决策**：保持单一窗口和连续底面，以逐像素 alpha 让已有外围留白透明，全部核心信息不透明；滚动文字裁切在读数区内。100% 的颜色、排版和组件不变。设置与菜单改称「边缘不透明度」，设置页说明作用范围。
- **取舍**：70% 不再表示整个窗口都以 70% 混合，桌面透视仅发生在窄边缘。接受透明面积减少，以稳定扫读为优先；没有添加卡片、装饰底板、阴影或第二个产品窗口。
- **兼容**：沿用 opacity 字段和值域，不迁移配置；移动位置保存不能把内部 Form.Opacity=1 写回用户的边缘偏好。请求、凭据、账号和调度语义不变。
- **实现与维护**：共享内部 LayeredFrame 负责预乘 alpha 与原生窗口呈现，释放 GDI 资源；系统高对比和原生呈现失败时保留不透明可读。真实合成截图、自动控件检查、物理操作和实际 DPI 检查分开记录。
- **后续状态**：本透明方案已被 ADR-015 取代。当前候选与验收边界见 [UAT.md](UAT.md)。

## ADR-013 · 按当前屏幕实际占用修订紧凑构图

- **依据**：用户将白色参考的约348×228实际像素设为新尺寸基准，指出144DPI下旧432×452窗口的占用P0；明确授权相应设计规范修订。
- **决策**：保持颜色、20段轨道、准确百分比与状态语义，将周期、数值/分段条和完整重置信息组织为横向三列。数值与条共享单元，取消全宽的独立重置行；测量内容决定宽高，不删信息、不自动缩字。
- **验证**：参考原图按原始像素展示于同一桌面，旁边为未指定诊断倍率的真实预览；记录真实窗口外框与DPI。多账号、长名称和极长金额按内容增长或滚动，不强制正常态高度。
- **取舍**：主窗紧凑文字使用独立固定字号规则，正文设备像素下限12px；设置与菜单维持原有操作字号。此处替代ADR-011最初288逻辑像素尺寸约束，保留其余视觉身份与业务边界。

## ADR-014 · 色彩承担连续分组和能源表达

- **依据**：用户R5明确要求不要单纯近黑底；上一轮轨道过小、服务商色沦为点缀，两个P1阻塞冻结。
- **决策**：公共底面改为可见蓝色，账号/设置分组用青蓝、品红紫、橄榄绿连续色带与服务商高饱和标题带。20段轨道横跨周期与数值两列，尺寸、时间列、字号不变。
- **边界**：不加卡片、纹理、渐变、Glow或背景网格；旧值轨道仍中性化，身份颜色不表示数据有效。70%仍仅影响外围留白；高对比使用系统颜色。设置与异常状态一同复验。
- **兼容**：替代旧近黑背景约束；不改变账号、请求、认证、配置和调度语义。R4尺寸验收目标保持。

## ADR-015 · U3 移除边缘透明度与旧配置字段

- **状态/依据**：用户 U3 明确要求移除边缘透明度设置和悬浮窗外围留白／边框；U4 的 UI Freeze 以该版本为基线。此决策取代 ADR-012 及 ADR-014 中关于 70% 边缘透明和保留 `ui.opacity` 的约束，历史截图和逐轮复审素材已按后续清理要求移除，当前决定继续有效。
- **决策**：主窗读数区与外围不再提供透明度设置；旧配置的 `ui.opacity` 在加载时忽略，下一次成功保存时移除。不得为了本机业务层恢复透明控件、外围留白或旧透明度字段。
- **验证**：SPEC FR-04、当前 `AppConfig` 读写及配置回归保持一致；不改变账号、认证、调度或正式程序替换边界。

## ADR-016 · 只保留当前维护资产

- **依据**：用户明确要求文件夹只留有用的文件，移除完成开发后的旧截图等资料。
- **决定**：保留当前源码、回归测试及合成样本、构建入口、产品和工程契约、当前候选、正式程序、运行中的 EXE、有效配置与备份。清理截图、逐轮评审材料、历史文档副本、一次性诊断脚本、旧构建和根目录早期实现。
- **配置**：根目录早期配置移至 `local-backup/`，保留内容并加入忽略规则；当前 `config.json` 路径与内容不变。
- **维护**：验证状态收敛到 TEST_PLAN.md 与 UAT.md；需要图片时用现有测试的 `--render` 重新生成。此清理授权替代早期任务中的历史文件保留限制。

## 变更规则

SPEC 中 FR-01～FR-12、本文已确认决策及 PLAN 的冻结边界组成架构基线。后续需求改变时先记录影响并同步三份文档；内部命名和满足既定契约的局部代码组织不必为每个小改动新增 ADR。暂不机械创建 DESIGN、DATA_MODEL、API_CONTRACT 等空文档，到了对应阶段且存在长期维护价值时再写。
