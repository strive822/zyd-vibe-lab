# 三端兼容范围

Codex、Claude Code、WorkBuddy 使用同一套 SKILL.md、相对引用、Python 脚本与项目 JSON，不依赖某端专有工具名、付费专家团、Node 或特定 MCP。Windows 安装器不需要预装 Git/Python；运行脚本时才按需准备 Python。

| 检查层级 | Codex | Claude Code | WorkBuddy |
| --- | --- | --- | --- |
| 完整 ZIP 生成、许可及文件核对 | 自动测试覆盖 | 自动测试覆盖 | 自动测试覆盖，带适配元数据 |
| Windows 临时目录安装、重复安装、中文空格路径 | 自动测试覆盖 | 自动测试覆盖 | 自动测试覆盖 |
| 安装后初始化及空项目拒绝交付 | 自动测试覆盖 | 自动测试覆盖 | 自动测试覆盖 |
| 客户端原生发现技能、实际联网和完整论文交付 | 安装时检查，未完成端到端验收 | 安装时检查，未完成端到端验收 | 安装时检查，未完成端到端验收 |

这里的三端测试是分发/安装/脚本兼容测试，不是调用三个实际客户端替用户写完论文。测试以真实结果为准，见 [验证记录](VALIDATION.md)。macOS/Linux 的通用文件和 Python 路径可由助手使用，零依赖启动尚未实测。

安装后的助手应分别验证：文件完整 → 宿主能发现技能或在当前会话直接读取入口 → Python 实际可运行 → 网络来源可达 → 所需文档能生成与渲染。只有各项实际成功才报告对应能力可用。发现失败时说明具体限制；不假装“已全端验证”。

更新 0.2 项目不删除材料：补做实际最终审查，并运行 review-snapshot 后 audit；润色前后源稿使用独立文件。无法恢复原稿时记阻塞，不伪造历史文件。
