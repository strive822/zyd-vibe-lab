# 真实文献检索与阅读

先读项目主题和方法，再读 [来源目录](sources.md)。使用宿主实际提供的搜索、浏览器或 API；不要调用并不存在的 MCP 工具。优先官方来源、出版页、合法机构仓储。中文与非 DOI 文献不能因 Crossref 未收录就认定不存在。

## 可执行检索

技能内 `scripts/literature.py` 提供不需要密钥的 Crossref 元数据检索与 DOI 查询，使用 Python 标准库。

```text
python <技能目录>/scripts/literature.py search "主题关键词" --limit 10 --out <项目目录>/literature/search-001.json
python <技能目录>/scripts/literature.py doi "10.xxxx/实际DOI" --out <项目目录>/literature/doi-001.json
```

示例 DOI 是占位格式，不是文献。脚本只访问 Crossref 固定 HTTPS 端点，不下载全文、不执行网页内容，不把候选项自动写成已验证引用。响应原文及时间、查询 URL、哈希一并保存。实际网络失败要报告，不用记忆生成假响应。

## 从发现到可引用

1. 在 `literature/search-log.md` 记录检索日期、网站、检索式、范围、筛选原因。按题目采用多个合适来源；无须为了凑数量使用无关数据库。
2. 候选文献核对标题、作者、年份、出版物和标识符，合并重复版本；预印本和正式版分别辨识。核查可见的勘误、撤稿或版本变更。
3. 到出版页或合法全文核验。为纳入文献保存项目内笔记，记录 URL、访问日期、读取范围（metadata/abstract/fulltext）、原文页码/章节或稳定定位信息。记录未能访问的部分。
4. 按 `contract.md` 将来源登记进 evidence。摘要仅能支持摘要明确报告的事实，不支持全文方法细节。元数据仅能支持书目信息。
5. 维护 `literature/references.bib` 或学校要求的引用库，保证正文引用与文献表双向对应。书籍、法规、档案、中文论文允许无 DOI，但必须有真实来源和定位。
6. 把重要论点映射到证据与位置，完成综述矩阵：问题、方法、材料、发现、局限、与本题关系。不要把多个摘要拼接成“研究空白已证实”。

检索不足时继续有依据章节，报告缺口。不要假装可以访问知网/万方订阅全文；可请用户通过已有授权提供文件。禁止绕过登录/付费墙；不把未公开题目或敏感材料原文发到公开检索服务。

## 可复核的证据笔记

每篇纳入文献建立独立笔记，至少写：实际书目信息、原始 URL、访问日期、实际读取范围、相关论点、原文页码/段落/表号、支持理由、局限及无法取得的部分。区分原文报告、自己的解释和待验证推测；不要把自己的总结写成原文直接引语。

一个论点引用多个来源时，claims 的 locator/rationale 按 evidence id 逐项说明各自定位与支持范围。没有定位的来源只能留在候选列表。不同来源相互矛盾时保留分歧，不以多数摘要代替判断。检索日志保留纳入/排除原因；数量与题目和学校要求相称，不预设必须凑够几十篇。
