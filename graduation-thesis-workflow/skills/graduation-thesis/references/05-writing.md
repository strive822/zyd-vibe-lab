# 基于证据的写作与润色

根据学校要求建立 `manuscript/outline.md`。没有统一的强制章数；系统、实验、人文论文可采用不同结构。先写已确定的方法和有证据的结果，最后核对摘要、引言和结论的一致性。

在 manuscript 下保存可编辑源稿。正文的研究结论、数字、引语和文献性论断登记入 `claims.json`，按 contract 连接到证据。计划、假设、作者解释与观察到的事实明确区分。引用不是装饰：原文必须支持该句，二手转引不能伪装亲读一手来源。

草稿缺证据时可使用显式标记 `【待证据：原因】`，并同时登记 blockers/unsupported claim；最终稿不得保留这些标记或将它们改写成肯定陈述。不补造致谢经历、导师反馈或原创性声明签名。

综述比较方法、证据和局限，不堆砌摘要。贡献表述与本科项目实际工作一致，不能将调用现成 API 写成提出新模型。毕业目标不等于降低真实性标准。

语言润色去空话、夸大和重复，保持术语、数据、公式、引用位置、条件和不确定性。可以按需使用宿主已有的 humanizer，但它不是事实审查，也不保证检测分数；使用前读其说明，冲突时保留学术准确性。润色后比较前后数字和结论强度，再跑审查。无需强制安装第三方 humanizer。

依据用户学校规定记录 AI 使用及作者负责的内容。若学校限制生成某些部分，调整为允许的整理、反馈与辅导；不得自动伪造符合声明。作者必须能理解和解释内容，答辩模块用于检查这种理解。
