## 发现的问题与修复

- GitHub 先前两次 repository 检查失败：today-todo 包中的 `assets/app.ico` 被本地忽略，云端没有对应源文件。现在将正式图标纳入版本控制，并识别 ICO 文件结构。
- 打包器此前扫描本地全部文件，可能带入忽略的运行数据。现在仅收集 Git 可见文件，并检查交付清单与当前源文件集合完全一致；新增或删除文件后必须重建交付包。
- ZIP 安全检查统一使用 `orig_filename`，防止 Windows 规范化文件名后遗漏反斜杠。白龙素材导入增加大小写冲突检查，拒绝覆盖已有清单和选中素材；回归测试覆盖这些行为。
- 白龙官方 740 MB ZIP 实际包含安装器，旧导入器只支持直接包含动画的 ZIP。现支持只读提取安装器的内嵌 payload.zip，不执行安装器；完整公开包 SHA-256 核验及 32 个素材文件导入均通过。
- Windows-MCP 原安装入口安装 PyPI 0.8.7，而非下载源码。新入口用固定源码的 uv.lock 创建项目内环境，已在隔离目录安装并验证 CLI。
- LibreTV 最新上游锁文件仍有 13 个审计漏洞；在上游源码基础上修复依赖，具体修改与哈希见 LibreTV 项目内的 SECURITY_PATCHES.md。
- 根项目数、待办安装入口、各独立项目恢复步骤、公开 ZIP 地址和版本说明统一核对；移除“首次上传后可用”的过时措辞。
- 新增待办、LibreTV 与公开下载验证的 CI；保留各项目现有测试。白龙默认检查不要求未随源码分发的大型开发动画。
- 云端发现 Chromium 持久化资料目录在测试结束后仍短暂被占用；浏览器登录回归改在独立 Python 进程执行，进程退出后才清理临时目录，避免固定等待 500 ms 的时序依赖。

## Agent 下载验收

每个项目均提供自己的 README 提示词、INSTALL.md、`delivery/<项目>.zip`、SHA256SUMS.txt 和 FILES.json。只下载、准备环境、运行和账号连接各自报告，不将任一步冒称全部完成。

发布后用不可变提交验证公开下载：

```text
python scripts/verify_published.py --ref <GitHub提交SHA>
```

该命令实际下载全部 10 个 ZIP 和对应清单，核对 ZIP SHA-256、CRC、路径安全、每个文件的哈希，并逐字节比较包内 README/INSTALL 与同提交公开源码。它只下载、检查，不安装或运行任何项目；CI 在 push 后使用当前提交执行同一检查。
