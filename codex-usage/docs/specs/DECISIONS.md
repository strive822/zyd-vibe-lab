# 决策记录

日期：2026-09-27；v0.4 决策基础。状态区分“已确认约束”“暂定建议”“待验证”。用户已在后续指令中授权 M1 单窗口原型，结果见 [M1-REPORT.md](../history/M1-REPORT.md)；用户已于 2026-09-30 确认 UI Freeze 并授权完整实施；下方历史决策按后续明确修订覆盖。

## D-01：全新立项与阶段边界 — 已确认约束

仅使用本次需求和后续确认。原立项阶段交付为规划文档与静态设计素材；用户随后明确授权 M1，现已有示例数据单窗口代码和运行证据。尚无真实数据接入或发布。视觉 Freeze 仍需用户设备验收；后续里程碑需另按范围执行。

## D-02：单用户、三家各一个账号 — 已确认约束

Codex 订阅、GLM Coding Plan、DeepSeek API 余额。多账号不纳入第一版。不同服务采用不同能力模型，不要求所有服务都具有五小时与周额度。

## D-03：Windows 桌面、Python + PySide6 / Qt Quick — 暂定建议

根据置顶、贴边、半透明异形命中、系统记事本和剪贴板需求，规划 Windows 原生桌面工具。业务模型和规则用 Python；QML 负责布局、状态反馈与动画；少量 Windows 集成收敛在平台模块。

| 方案 | 适配点 | 主要代价 | 结论 |
| --- | --- | --- | --- |
| Python + PySide6 / Qt Quick | Python 业务逻辑、声明式界面、图形与动画；Qt 提供桌面集成 | QML 学习、打包体积、Windows 透明命中需实测 | 首选候选 |
| C# + WPF | Windows 窗口能力、矢量界面与成熟绑定 | 需要额外学习 C#/XAML；仍要验证复杂窗口命中 | 原型失败时的备选 |
| Electron / WebView 方案 | Web 排版与动画方便 | 常驻资源、跨边缘输入处理和前端技术面增加 | 首版不优先 |
| 传统控件式小窗 | 简单信息表容易 | 自定义半圈、动画和跨层视觉需要更多定制 | 不作为视觉实现默认 |

这只是工程判断；Qt 官方提供 Python/QML 数据桥接与托盘能力，并不证明本产品的所有交互已跑通。版本在实施开始时依据兼容矩阵锁定；规划不猜测安装版本。M1 是技术选择的证据门槛。

资料：[Qt QML 与 Python](https://doc.qt.io/qtforpython-6/tutorials/qmlapp/qmlapplication.html)、[Qt 桌面集成](https://doc.qt.io/qtforpython-6/overviews/qtdoc-desktop-integration.html)、[WPF 窗口](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/windows/)。

## D-04：一个进程内分模块，无服务端 — 暂定建议

建议模块：领域数据与时间规则 / 用例协调 / 三家适配器 / Windows 集成 / 持久化 / QML 展示。它们是代码边界，不是微服务。

Qt 网络与进程事件接入 UI 事件循环；首版优先 QNetworkAccessManager 与 QProcess，避免无必要地叠加两个异步事件循环。UI 只消费状态，不直接拼接 API 请求。领域规则可在不启动窗口的情况下验证。

## D-05：数据源优先采用官方可解释路径 — 暂定建议

Codex 首选官方 app-server 的额度读取；DeepSeek 首选官方余额接口；GLM 首选官方用量插件所用的监控路径。不得把 Codex 应用内的聊天工具当成独立产品的运行依赖。

Codex 登录来源和凭据生命周期须在 M2 明确：只发读取请求；不自动更换账号、不购买/消耗额度重置；授权过期时指引用户在官方客户端完成登录。子进程自身的凭据刷新行为需要验证，不作“绝不写认证文件”的未经证实保证。

GLM 官方示例的可读源码只是接入证据，仍缺本账号响应与字段对照，不能称全面接入完成。

## D-06：把恢复、更新与常态优惠分开 — 已定设计原则

配额恢复属于服务端语义；数据更新属于工具请求结果；优惠属于版本化时间规则。三个时钟和字段分开建模。倒计时到零只触发核验，不把额度归满。优惠标记不改变额度、余额或服务端数据。

## D-07：半圈功能球服务于快捷操作 — 暂定建议

最多 2 个常用复制位，另有更多文本、每日提醒、设置，共 5 个外围球。完整列表容纳其余文本，避免不断加球导致目标过小。说明由用户填写；默认可以沿用动作和名称。入场到位后的半圈位置固定；选中状态只改变颜色、描边或符号，不自动换位。贴边展开/收起期间有单独的进出场动画，见 D-20。

## D-08：记事本采用文件交接 — 已确认需求，交接方案暂定

每项独立 UTF-8 文件、稳定 ID。应用监听已保存内容；不以记事本退出作为完成信号。名称、说明、排序保存在配置中，正文保存在对应文本文件。预存文本是本地明文；服务 API 凭据另用 Windows 凭据存储。

## D-09：轻量本地持久化 — 暂定建议

设置/账号引用/文本元数据/提醒定义存版本化 JSON；状态缓存与提醒账本分离。写入采用同目录临时文件加原子替换，保留上一份可恢复配置。单进程锁避免重复实例。当前数据量不需要服务器或数据库；需要复杂检索、同步或多进程事务时再评估 SQLite。

## D-10：提醒是常驻应用能力 — 暂定建议

先实现应用运行期间的每日提醒、同日恢复补发和去重，不增加 Windows 服务或系统任务调度器。电脑关机/休眠不保证准时提醒。未来如需要退出应用后也提醒，应单独扩展范围。

## D-11：视觉先证明再扩展 — 已确认约束

## D-18：B 的叶形与对照结构 + C 的内部时间槽 — 用户已确认

保留 B 的温白叶形、橄榄色强调、窗口行/服务列和独立余额基线；采用 C 的固定顶部时间区。悬浮 Codex 时只替换时间槽内容，不在下面延展面板、引线或新块，不改变外围轮廓、主数或功能球位置。

## D-19：自适应三单位和逐位过渡 — 需求已确认，参数为初始规范

用户选择长时间天/时/分、短时间时/分/秒。初始以 24h 为界；首个数值不补零，后两项两位，零值单位保留。普通倒计时变化只动画实际改变的字位；10→9 等位数减少时退出对应槽位，单位位置和计时总宽不变。24h 边界按完整三元组切换，避免旧数字配新单位。

滑动约 160 ms、整组三单位切换约 180 ms；都可被最新状态安全打断。减少动态效果时改短淡入。源时间变化、休眠恢复或时钟跳变直接过渡到当前结果，不播放积压秒数，不假装经过所有中间值。没有把静态动效示意当作已经实现或测过的动画。

## D-20：明确悬浮入口与功能球入场 — 用户已确认动效要求，参数暂定

用户要求：从屏幕边缘的收起球/半球悬浮展开时，带功能的小球也要有出现动效。当前定义为中心先展开，五球沿半圈顺序短距离舒展、淡入并轻微缩放到位；离开整体区域后延时反向回收，中途返回从当前状态反转。具体时长、间隔和距离见 DESIGN 第6节，均待 M1 实测。

两种悬浮分别处理：可见贴边球触发展开；下方 Codex/GLM 概要列（名称或五小时/周剩余量）触发内部时间区的内容切换。截图的大计时是阅读区。默认标题补充具体窗口，区分剩余时长、绝对恢复时刻和最近成功更新。

以上是 M0 时的动效定义；M1 已按用户后续指令实现示例数据窗口与动效，验证边界见 [M1-REPORT.md](../history/M1-REPORT.md)。

## D-29：鼠标只靠悬浮查看，点击不锁定 — 用户明确修订

用户实际点击后发现浮窗不再自动收起，并明确要求“不要这个点击，就悬浮就行了”。旧代码把平台行点击和任意叶片空白点击都设为 `pinned=True`，空白点击尤其没有可见理由。当前鼠标点击不再固定浮窗；平台点击只立即展示其详情并清除鼠标焦点，移出仍经 700 ms 收起。键盘聚焦与 Esc 路径保留。展开态“半耗”和“半价”首字使用同一字体与像素相位单独绘制，150% Qt 截图中两枚“半”的对应 16×20 像素区域逐点相同。用户已在真实桌面确认点击后移出自动收起。

原生注入点击曾证实平台与空白点击后均可收起；复核又发现鼠标停在收起球原位时，球在展开后从悬浮判断里消失，可能形成周期性展开/收回。现在原位仅保留为悬浮热区，不加入展开态原生窗口遮罩；因此停留不会启动回收，透明区域的桌面点击仍能穿透。用户已在真实桌面确认收起球静止悬浮约 3 秒持续展开。

## D-31：四边拖动与方向性构图 — 用户实际操作确认

## D-32：键盘焦点与动作共用索引，顶部提醒保留安全边距 — 待独立复审

## D-33：保存内容以独立文件为准，元数据草稿独立于位置写入

记事本进程复用、保持标签打开和原子替换均不等于未保存。监听文件与目录并重新挂接已替换文件，丢失时立即失效；运行时不累积正文缓存。位置保存和其他设置变化不覆盖未提交的名字／说明草稿。

## D-34：日期账本先领取，通知提交与已读分开

每条每日提醒按本机日期形成唯一事件，先持久化claim再向系统提交。打开提醒列表不清未读；全部已读是明确操作。损坏账本暂停重复提交而不猜测历史。DST缺失／重复时刻按DATA_MODEL规则处理；不承诺跨崩溃严格一次送达。

## D-35：设置是普通独立窗口，不能锁住悬浮叶片

设置无顶层置顶和叶片owner依赖；焦点移到记事本／浏览器可覆盖设置。仅有锚定文本列表或菜单维持对应临时锁。取消鼠标点击也必须释放 incidental focus，离开计时被锁拒绝后重新启动一次。

## D-36：低功耗必须保留持续悬浮检测

仅靠Windows Enter唤醒会在非激活、有遮罩的工具窗口中漏掉进入，用户实际发现无法展开。恢复持续检测：完全收起且指针在外时只检查圆形，64ms轮询；指针进入／展开／拖动时32ms，保留100ms意图阈值。静止收起不重复变更系统光标、不每秒重绘。性能工具只读观察既有进程，不能再启动第二颗测试球。性能与正常交互须在当前版本共同通过。

## D-37：私有便携候选独立运行依赖，构建身份覆盖源码和构建输入

使用现有Python3.12.10官方嵌入发行、必要Qt模块／插件、tzdata和许可文件；不引入额外打包器。无shell的窗口启动器传递参数，运行时隔离site和外部Python环境并禁用bytecode写入。候选哈希覆盖源码、运行时校验值、依赖、启动器、构建器与随包文档；旧候选保留作历史，不能代替当前修复。干净Windows、长时间驻留和签名发布另行验收。
