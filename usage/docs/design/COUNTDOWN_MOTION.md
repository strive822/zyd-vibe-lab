# 三单位倒计时与数字动效

状态：v0.4 设计规格，尚未实现或实测。日期：2026-09-27。

## 1. 用户要求和初始规则

已确认：长时间显示天/时/分，短时间显示时/分/秒；位数发生变化也要有动效。初始分界采用24小时，可在设计收敛时调整。

| 剩余时间 | 三个单位 | 格式例 |
| --- | --- | --- |
| >= 24h | 天 / 时 / 分 | 3天00时00分 |
| < 24h | 时 / 分 / 秒 | 1时30分00秒 |
| 到零、服务端未核验 | 时 / 分 / 秒 + 待确认状态 | 0时00分00秒 |
| 源未提供恢复时间 | 未提供 | 不生成假零值 |

每个窗口独立选择单位模式；同屏两条计时可以使用不同模式，某一条跨界不切换另一条。首个数值不补零；后两个数值固定两位；零值单位不省略。绝对恢复时刻仍按 HH:mm 或 MM/DD HH:mm 表达，三单位规则仅针对剩余时长。

同一画面中的两个窗口用同一个 now 计算。正剩余时间向上取整到秒，负数夹到零。DHM 使用天、剩余小时、剩余分钟，省略不足一分钟的秒。显示不触发每秒联网。

## 2. 固定槽位

每个倒计时有三个固定单元：数字槽 + 单位。使用等宽数位，首单元为当前窗口范围预留足够宽度，数字右对齐。其他两单元各保留两位。单位锚点和整个倒计时宽度固定。

10→9 时，十位退出，个位从0过渡到9；空出来的位置保留为空槽，不推动“时”字和后两个单元。9→10 时，新位从预留位置进入。所有动画局限在计时区的裁切边界内。

字宽预留必须在选定字体和实际 DPI 下验证，不能只开启“等宽数字”就认为不会重排。正文不低于12DIP，悬浮计时数字目标14DIP；字号不随位数反复变化。

## 3. 三种主要过渡

| 变化 | 过渡方式 | 初始时长 | 不允许的行为 |
| --- | --- | --- | --- |
| 普通数字变化 | 仅变化的字位：旧字上移淡出，新字从下方短距离进入 | 约160ms，位移4–6DIP | 所有数字一起跳、滚过一串不存在的中间值 |
| 位数增减 | 新增/消失的字位在预留槽内进入或退出，其他锚点不动 | 与数字变化同步，约160ms | 小时区突然收窄，单位、额度表或球被推挤 |
| DHM/HMS 切换 | 整个三元组以完整快照交替；数字和单位一起换 | 约180ms | 先换单位再换数值，生成“23天59分59秒”之类混合态 |

采用平稳减速，无过冲、弹跳、三维翻牌或持续转轮。跨单位制时允许整层轻淡入/淡出；不能把上一模式某一项与下一模式的另一项拼成一个可读状态。

## 4. 与其他交互的优先级

- 平台悬浮切换：整个时间槽约170ms交叉切换，标题、窗口时间、单位和更新时间作为同一份内容；不叠加跨账号的逐位滚动。
- 普通 tick：对当前已显示的平台做局部字位更新；借位涉及的多个字位在同一帧开始。
- API 返回新的恢复时刻、系统时间大幅改变、休眠恢复：过渡到最新完整结果，不播放积压秒数。刷新前后的值不必逐个连续经过。
- 动画未结束又收到变化：合并到最新状态，保留当前视觉进度作为起点；不排出长队。
- 隐藏时停止数字渲染动画，重新展开直接取当前剩余时间。倒计时的时间本身没有暂停。
- 减少动态效果：取消位移，仅短淡入或即时替换；状态反馈仍然存在。

默认焦点事件到点后保留“待确认”，不因为本地变零就宣称额度恢复或悄悄跳走。取得新成功快照后再重新判断默认恢复事件；额度由服务端数据更新。

## 6. 当前证据边界

本轮只有静态两状态图、数字过渡示意和这份规格。Microsoft YaHei UI 的字宽估算中，“周09/30 02:10”12DIP加8DIP间隙与“23时59分59秒”14DIP约需182.67DIP；内部时间区预算约190–194DIP。该结果不是Qt真实渲染、中文回退、DPI或动画验收。

M1 才实现一个原生窗口中的这一交互，并留下至少一次10→9位数变化和一次24h单位切换的录屏。不能用静态箭头或文字描述宣称动效已经完成。
