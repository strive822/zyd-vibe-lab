# 实施路径

状态：M1 已于 2026-09-30 UI Freeze；用户授权按本计划自主实施整个首版范围。当前 M2–M5 代码切片已接通，M6 与尚未关闭的设备／交付验收进行中，见 [实施状态](IMPLEMENTATION.md)。M0/M1 下文保留历史验收定义。2026-09-30 用户另行授权四颗常用复制球并保留更多文本。

## 执行规则

- 当前推进 M6，同时关闭前序真实数据、交互与设备验收；M1 核心 Design Identity 已 Freeze。
- 用户已授权按照 Milestone 连续实施；常规实现和修复不等待逐步确认。Scope、Design Identity、重大架构、API 契约、破坏性存储变更或重要外部依赖需要变更时再询问。
- UI 必须先完成 M1 Visual Prototype Milestone，再逐页扩展。
- 每阶段有独立成果和验收记录。失败时仅修复该阶段，不借机扩展功能。
- 每阶段交付给用户可观察的结果、测试证据和仍未验证的边界；脚本通过不替代真实鼠标、键盘和显示器验证。
- 本次按用户明确要求自主实施，逐阶段执行类型检查、Lint、测试、真实运行、修复、回归并更新状态。
- 外部账号或物理设备的验收证据未到时，可推进不依赖它们的独立切片；原门槛继续标为未验收，最终 Done 不豁免。
- 2026-09-30用户将本次个人使用的显示验收收敛为当前单屏150%，无需切换其他缩放；其他DPI／多屏物理兼容范围标未验证，不阻塞当前设备交付。下文原多屏验收定义保留为未来兼容目标，不将模拟写成物理通过。

## M0 — 产品与设计定义（历史阶段）

输入：本次需求、账号类型/单账号确认、官方资料。  
工作：需求范围、信息架构、窗口状态、数据语义、技术候选、静态 A/B/C；按用户反馈重新探索小型非矩形中心。  
输出：7 份主文档、最新 B+C 融合图、倒计时动效规格及生成记录；旧候选与归档已按要求移除。  
依赖：无。  
验收：
- 五小时、周额度、余额、更新时刻和优惠时段不混淆。
- 单账号、系统记事本、多条具名文本、每日提醒均有明确范围。
- 本轮三家概要常显、悬浮明细和动效需求已确认。
- 已完成本轮 18 个概念方向的内部结构化比较，逐项包含 10 个设计维度；6 个未通过约束检查，余下 12 个中保留三种不同信息模型并生成静态图。
- 已确认：B 的叶形与窗口对照组织，融合 C 的固定内部时间槽；长时间天/时/分、短时间时/分/秒，位数增减需要动效。
- 尚未满足：融合稿精修与尺寸收敛；实际命中、数字过渡、DPI 和异常态均须后续验证。
- 用户已选 B+C 融合；需完成精确尺寸、状态与动效定义的收敛，当前不称规划冻结。
风险：概念图在小尺寸下未必可读；所有尺寸与动效仅为候选。  
停止点：文档和视觉方向收敛完成后停止，等待明确的实施指令。

## M1 — Visual Prototype Milestone

输入：用户另行授权实现；已选定的 DESIGN；目标 Windows 设备。  
依赖：M0。  
仅实现：
1. 一个真实 Windows 顶层浮窗，右侧贴边的收起球和展开态。
2. 固定的三家示例数据，包含正常、旧数据、未连接三类可切换展示状态。
3. 暂定五个功能球的布局、贴边展开时的入场/回收动效和到位后的悬浮反馈；只接通一条代表性交互：
   收起球 → 悬浮后中心展开、五球依次舒展到位 → 指向下方 Codex 列的名称或任一额度查看时间明细 → 穿过间隙到一个具名复制球 → 复制固定示例文本 → 离开延时回收。
   这条链同时验证窗口展开、功能球进出场、平台明细和球选中反馈；在同一个时间槽补测数字借位、位数增减与24h单位切换，不扩展为完整设置或全部动作。
4. 减少动态效果模式；键盘/点击可展开的基本替代入口。
不实现：真实账户接入、设置全页、记事本、提醒调度和跨屏完整逻辑。原计划只验证右边；用户在 M1 实际使用后明确要求同一窗口可拖至四边并自动吸附，现已在本阶段补入四边朝向与拖动，但多屏接缝和混合 DPI 仍留在 M4 系统验收。

输出：单页面/单窗口原型、截图对比、短操作录屏、目标设备测量表。  
验收：
- 按融合方向尝试约 236 × 208 DIP 的叶形核心，包含功能球的整体目标不超过约 300 × 300 DIP；常态和平台悬浮态使用相同外框。记录实测尺寸，不能用大图缩放感代替。
- 常显 B 的窗口行/服务列对照表；顶部固定时间槽，常态按用户最新选择显示 Codex／GLM 四个窗口中最低的已知剩余，恢复时刻已知则并列显示倒计时，悬浮显示该家的双窗口时间和更新时刻。未知不当作零；禁止外接明细块；主表、单位锚点及按钮不移动。
- 收起球的 C/G 两枚表盘各取本家 5h／周较低已知值，并以 H/W 标明选中窗口；如果两窗均未知，断续环不能被误认作零。展开交接须抵达对应的 5h 半弧或周短轨。
- 主读数目标 16–22 DIP，平台名/正文 12–13 DIP；若目标尺寸放不下，先调整排版并与用户收敛，不偷偷缩字或放大主窗。
- 100% / 150% / 200% 缩放可读；无裁切、时间文字挤压。
- 鼠标穿过中央区域、平台明细与功能球之间的空隙，不误收起；快速跨越三家时无明细闪烁和错绑。
- 录屏能看清五个球按半圈顺序舒展、淡入和回收；不能只有中心动效，也不能把已展开后的选中效果冒充入场动效。半圈落点不漂移，隐藏球不截获输入。
- 右图由下方 Codex 列的名称和两项剩余额度均可触发；上方标清具体恢复窗口与数据更新时间，从平台移到时间区可持续阅读。
- 悬浮、返回和减少动态效果均有明确反馈；只有静态图不算动效验收通过。
- 透明区域可以点击桌面；悬浮不抢焦点；复制仅改变剪贴板。
- 动画可中途反转；连续进出 30 次无重复窗口、卡住或抖动。
- 60 Hz 目标环境的动画帧耗时目标 p95 不超过 20 ms；记录硬件、采样方式和结果，失败需降复杂度后再测。
- 用户亲自确认观感、尺寸与实际悬浮操作。未确认不得宣告视觉冻结。

技术止损：若 Qt 原生窗口命中、透明区域或输入焦点无法稳定通过，保留同一设计，在最小范围评估 WPF 原型；不直接扩展全产品。

## M2 — 数据来源与真实语义验证

输入：M1 壳层、用户在本机配置的账号授权。  
依赖：M1；此阶段不扩展页面。  
工作：
- Codex app-server 只读查询；确认是否同时存在 5h/周窗口和多额度桶。
- GLM 国内个人版官方查询路径；验证额度窗口、百分比方向和恢复时间字段的当前真实含义。
- DeepSeek 余额；币种和小数精确保存。
- 统一状态模型、超时/取消/退避、最后成功数据保留。
- 常态优惠计算；校验 DeepSeek 年度节假日来源及覆盖范围。

输出：三份脱敏响应夹具、接口映射表、错误状态截图、规则边界测试。  
验收：
- 与各家官方界面逐项对照，记录时间差。
- 不使用模型推理请求测试额度；只使用额度/余额读取能力。
- Codex 不同窗口不能依赖 primary/secondary 固定位置。
- GLM 恢复时间如果只能证明“下一批补回”，UI 不声称“全部重置”。
- 网络/鉴权/429/缺字段只影响对应平台。
- 所有真实密钥不进入仓库、截图、夹具和日志。
风险：GLM 官方插件实现不等于长期稳定 API 合约；Codex 安装位置与认证上下文可能不同。  
失败处理：明确“暂不可用”并记录证据，不以猜测或虚假倒计时替代。

## M3 — 完整桌面壳层

输入：通过 M2 的数据源和状态模型。  
依赖：M2。  
工作：四边贴靠、角落选择、向内展开、拖动与固定展开、托盘、显示器切换、DPI 变化、任务栏工作区、休眠恢复。  
输出：桌面集成模块与原生交互验收记录。  
验收：
- 左右上下、双屏不同缩放、拔屏、任务栏变位后窗口可找回。
- 多屏接缝不自动吸附。
- 完整球/半球的关键提示始终在可见区域。
- 所有浮窗、菜单、工具提示与设置窗口有一致且可操作的焦点层级。
- 连续拖动/进出/重启不会丢失配置。
风险：不同 Windows、显卡和远程桌面组合的透明窗口行为须实测。

## M4 — 具名复制与系统记事本

输入：桌面壳层和 Snippet 数据模型。  
依赖：M3。  
仅新增界面：设置窗口的“快捷文本”区、更多文本小面板。  
工作：名称/说明/图标、添加编辑删除、排序和四个常用位（2026-09-30 用户修订；M1 基线为两个）、更多文本、记事本、已保存内容监听、Unicode 剪贴板。  
输出：从添加文本到复制的完整链路。  
验收：
- 同名冲突可区分；重命名和排序不改变内容归属。
- 多记事本标签/窗口、进程复用、Ctrl+S、删除/移动文件、空文本均正确。
- 一项编辑不替换另一项；剪贴板写入失败不误报。
- 实际复制保留中英文、空格、换行和 Unicode。
- 透明空白和文本列表的滚动符合原型规范。
风险：不能把记事本进程退出当作“保存完成”。

## M5 — 每日提醒与剩余设置

输入：Reminder、Occurrence、Clock 抽象和持久化。  
依赖：M4。  
新增界面：每日提醒区、账户设置区、窗口行为区。  
工作：每日时间/事项/启停、去重、同日恢复补发、通知与未读、时区变化、可选启动项。  
输出：提醒链路与逐页设置验收。  
验收：
- 临近下一分钟的提醒可实际触发；无需等待一天验证。
- 时钟前拨/后拨、睡眠恢复、重启、日期跨越不重复轰炸。
- 系统勿扰时不宣称用户已看到通知。
- 应用未运行/电脑睡眠期间不承诺提醒；设置中说明这一运行边界。
- 每完成一个设置分区即做视觉与键盘检查，再扩展下一个分区。

## M6 — 统一打磨、可靠性与交付

输入：前述阶段全部通过。  
依赖：M5。  
工作：主窗/设置/列表/提醒跨屏一致、字体与图标、键盘导航、长文本、错误文案、低功耗、打包与干净环境启动。  
输出：安装或便携包候选、README、必要运维说明和已知限制。  
验收：
- TEST_PLAN 的必测项通过，未通过项有用户可理解的边界。
- 启动、长时间驻留、网络切换、三家连续失败均无忙轮询。
- 初始目标：收起且空闲时 CPU 平均低于 1%，内存目标低于 200 MB；统计包括应用自有的 Codex 子进程，排除用户已有 Codex 窗口。只在参考设备上报告测量结果。
- 包含 Qt/Python 运行依赖与授权说明；在无开发环境的 Windows 测试。
- 最终发布仍需用户明确授权，不自动发布、注册启动项或更新其他软件。
