# rea

面向 Agent 的逆向分析工具入口，用于检查二进制、应用与运行行为。本目录维护固定版本的准备脚本、配置和上游来源；分析引擎按实际需要配置。

## 功能与使用范围

REA 把分析工具交给 Agent 或命令行调用，适合研究“某个已有应用的功能如何实现”，并把结论和证据用于自己的实现。这里维护固定版本的准备入口，不把下载完成称作分析能力已经接通。

| 分析对象 / 环节 | 上游能力及前提 |
| --- | --- |
| JavaScript / Electron | 静态分析提取后的应用目录或 ASAR，梳理代码结构和实现线索；不要求原生反编译引擎。 |
| 原生二进制 | 可连接 Hopper、Ghidra 或 IDA 等分析引擎；必须先具备对应环境与授权，不能只靠 CLI 下载包。 |
| .NET 与网页应用 | 上游提供相应分析路径；根据目标类型选择工具，结论附证据和局限。 |
| Agent 工作流 | setup 可为支持的客户端准备 MCP 与配套流程；先展示计划，确认后才写宿主配置。 |
| 命令行调用 | 可以先执行固定版本 `--help` 核对当前命令，再分析明确授权的目标。 |
| 可重复准备 | 本地脚本从锁定 npm 包取得文件并校验，保留许可证，不升级其他分析工具。 |

例如：“分析我提供的 Electron 应用目录，说明它如何实现搜索，列出代码位置和不能确认的部分。”目标样本、报告和分析结果保留在独立工作目录，不进入这个公开源码仓库。

上游功能依据：[固定提交说明](https://github.com/morluto/rea/blob/160d821ac9a0310afcb8d1fc427862dd6508add5/README.md)。本机是否具备某个引擎、是否已经接入当前客户端，仍需分别实测。

## 直接让 Agent 帮你使用

把下面这段话复制给具备联网、文件读写和运行能力的 Agent。
它应先读本项目 [INSTALL.md](INSTALL.md)，完成提示词授权的下载、核验与使用步骤。
只想保存文件时，把“安装/运行”改成“只下载，不安装、不启动”。

```text
安装并使用 https://github.com/strive822/zyd-vibe-lab 里的 rea。先读取该项目 INSTALL.md，从固定 Release 下载对应成品并校验，按项目类型安装或启动；保留已有数据与配置。日常使用不克隆开发仓库、不重新构建前端；只下载时不安装或启动。
```

独立项目目录，保留原来的固定版本、个人使用配置和下载校验。无须获取其他项目。

- [Agent 下载与恢复](INSTALL.md)
- [来源与许可](THIRD_PARTY.md)
- `profile/`：启动入口、使用说明和许可副本；这是恢复材料，不能当成已安装程序。
- `assets.json`：仅包含本项目所需的固定下载来源、大小与 SHA-256。
- `restore.py`：只恢复本项目，目标必须是新目录。

# 我的 REA 使用入口

保留 rea-agents 6.8.0 npm 发布包使用方式。当前没有已确认的个性化 Agent 接入配置，因此恢复只准备包和说明，不自动执行 setup 或安装分析引擎。

Windows PowerShell，有满足包 engines 的 Node/npm 时：

```powershell
npx.cmd --yes rea-agents@6.8.0 --help
npx.cmd rea-agents@6.8.0 setup
```

第一条是帮助检查；第二条按原向导先展示将修改的配置与安装计划，再由用户确认。该包允许 Node ^22.23.4、^24.22.1 或 >=26.12.1；Node 24.22.1 满足 Node 版本条件；运行时需另行在本项目内准备，但 REA 的引擎和实际目标分析需单独验证。WSL 请使用 WSL 的 Node/npm 和该环境的配置，不把 Windows 路径混进去。

原下载包也可作为 `npm install` 的本地来源，但不强制全局安装。保留包内原许可、THIRD_PARTY_NOTICES 和 licenses。源码参考提交为 `160d821ac9a0310afcb8d1fc427862dd6508add5`，不是 npm 包构建结果的替代证明。

仅分析有权处理的目标；区分观察、推断和未知项；保留证据出处。不要自动安装/升级无关 Node、Java、Ghidra 或其他引擎，不宣称具备未实测的原生反编译能力。
